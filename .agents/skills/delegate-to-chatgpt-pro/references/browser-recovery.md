# 浏览器故障与任务恢复

仅在启动预检、遇到浏览器故障、需要保存状态或恢复任务时读取。具体 API、插件路径和恢复动作服从当前浏览器 Skill，不复制旧会话的初始化代码。

## 按新证据判断故障

| 现象 | 处理 |
|---|---|
| 没有可调用浏览器执行工具 | 按当前 Skill 的工具发现流程检查；不要把工具未暴露误诊为插件文件缺失。 |
| 初始化明确报告模块缺失 | 记录本次错误时间、模块绝对路径和当前插件版本；允许用本地只读检查确认该路径是否存在。文件仍缺失则报告安装问题，不反复初始化，不自动拼接其他版本文件或修改插件缓存。 |
| 文件已修复，但仍重复旧导入错误 | 按当前官方恢复流程检查；规则允许且错误支持运行状态失效时重置一次并重新初始化。只有新调用结果才能证明恢复或失败，不能引用旧报错作为新证据。 |
| 初始化成功，但浏览器发现或选择失败 | 先读取运行时的 bootstrap-troubleshooting；扩展通信问题读取 chrome-troubleshooting，再按指引处理。 |
| 标签丢失或列表为空 | 保留有效浏览器连接，重新取得或创建标签。不要因空标签列表重置运行时。 |
| 登录过期、验证码或二步验证 | 保存任务状态，请用户在所选浏览器完成登录；不索取凭据，不跨浏览器绕过登录。 |
| 页面限额或所选模式不可用 | 记录可见提示，按主文件的模式和预算规则处理。不能诊断为插件损坏。 |
| 消息发送超时，无法确认结果 | 回到原对话检查可见消息和任务编号，确认是否已发送；无法确认则记录 send_unknown，暂停重发。 |

重装建议必须基于新证据。不要把“完全退出再重装”作为统一兜底。技术细节写入诊断记录，用户进度说明只需交代连接状态、影响和下一步。

## 持久任务记录

在项目允许的输出目录保存 `delegation-state.json`。最少记录：

- `schema_version`、`task_id`、`updated_at`、`phase`。
- `browser_surface`、`conversation_url`、`model_label`、`reasoning_label`；未观察到的值使用 null，不猜测。
- `checks`：connection、page_readable、mode_selectable、upload、send、download，分别记 passed / failed / unverified 及观察时间。
- `authorization`：用户授权来源摘要、项目与数据范围、接收方、允许操作和禁止操作；不保存凭据。
- `baseline`：仓库路径、HEAD、相关工作区文件哈希、输入包路径及 SHA-256。
- `dispatch`：本轮任务编号、输入包哈希、发送状态 prepared / sent / send_unknown、最后确认时间。
- `deliveries`：交付物本地路径、SHA-256 和对应输入基线。
- `verification`：已运行的命令、退出码、证据路径、尚未通过的验收项。
- `rework_count`、`blocker`、`last_successful_step`、`next_action`。

记录是恢复线索，不是实时事实：恢复后检查原对话可见状态、附件是否可访问、模式是否变化、工作区是否漂移。确认后从最后成功步骤继续，避免重做打包、重复发送或覆盖新改动。对话链接和交接文件仅保存在用户授权的项目位置。
