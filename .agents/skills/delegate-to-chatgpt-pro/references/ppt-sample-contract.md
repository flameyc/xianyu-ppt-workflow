# PPT样稿网页协作合同

网页负责风格拆解、样页设计和按需生成素材；Codex负责需求来源、接回可编辑PPT与实际验收。先做少量代表页，避免整套做完才发现风格错误。两条制作路线都能使用。

## 执行

1. 本地核对需求、教案/文案版本、交付格式、章节页数、计费页数和可编辑边界。客户指定标题与环节不得被创意文案替换。
2. 选择已获授权外发的最小内容：去身份简报、1—3张必要参考图、样页文案。不要上传整份微信记录、客户联系方式或模板库。已有授权覆盖就继续；不足时先做好可审阅的最小包，再确认外发范围。
3. 浏览器预检按主技能；任务包保存在本地订单 `delegation/sample/`。记录输入哈希、事实版本、参考图来源、实际网页模式和对话地址。
4. 把下面合同填实再发送。已有认可参考时沿用，不强制重选风格；没有明确参考时先少量候选，避免无限探索。
5. 收到结果先检查真实图片/文件是否可取。只有文字方案就登记为方案，不宣称图片样稿已完成。中文普通文字优先在本地原生排版，复杂插画保留图片；不要先压成整页图片再假装可编辑。
6. 本地核对文案、看图、检查参考一致性，再给用户样稿。用户选定/客户确认分别记录来源和版本；网页自评不等于确认。
7. 确认后固化色板、字体、人物、纸张/图形语言、页型及图片与文字层边界。按页型批量扩展；改稿只传反馈差异和受影响页。首次真实运行才可登记“网页PPT样稿闭环通过”。

## 发送内容模板

以下内容由Codex填好，去掉占位项：

```text
任务：<编号>；类型：ppt_sample；事实版本：<版本>
用途/受众：<已知事实>
客户最在意：<来自客户的要求，标明未确认项>
样稿范围：<通常封面＋代表内容页；需要时增加密集/互动页>
文案：<逐页准确文字；必须原样保留的标题/数字/步骤单列>
参考：<已授权图片和提炼特点；不能访问本机路径>
风格约束：<已认可方向；无方向则写待选>
制作路线：<省Token复用/追加定制投入>；两者均保持认可风格。
交付：样页预览；按页列出的准确文字；无字背景/插画等可取得素材（能力可用时）；原生文字层与图片层的分工；尚未解决项。
若当前无法生成或导出图片，明确返回“仅设计方案”，不虚构下载链接。
不改客户事实，不擅自增页或承诺动画/全矢量可编辑。插画应帮助表达，不只重复装饰。
不要输出长篇工作过程，给可直接接回的结果。信息不足只列影响样稿的必要缺项。
```

## 样稿锁定记录

本地保存 `style-lock.json`，包含 `status`（draft/owner_selected/customer_confirmed）、`evidence`、`sample_files`及哈希、`fact_revision`、`palette`、`fonts`、`characters`、`page_types`、`editable_boundary`、`must_keep`、`change_scope`。未确认时不能填customer_confirmed。系统目前由Codex维护这份记录，尚无自动状态闸门。
