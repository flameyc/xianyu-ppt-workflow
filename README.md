## 从这里开始

- 双击 **打开工作台.cmd**：刷新并打开本地订单工作台。
- 在Codex中打开本目录作为项目，或继续在当前任务提出需求；当前任务仍位于E:/技术，不声称已改变应用的项目设置。
- 支持工作区文件的编辑器可以打开 **闲鱼PPT自动化系统.code-workspace**，其中只包含本项目。
- 新单直接说：**“按这个工作区接一单：用途是……，资料在……，客户要求……，先做样稿。”**
- 改稿直接说：**“订单编号……，客户新反馈是……，在这个版本……上修改。”**
- 你不需要自己写JSON或逐条运行脚本；当前Codex负责整理任务并调用工作流。

## 首版已经能做什么

| 步骤 | 已实现 | 仍需要判断的部分 |
|---|---|---|
| 接单 | 订单隔离、需求记录、真实/历史/演示区分 | 用途、报价范围与承诺由本人确认 |
| 收资料 | 只读快照、内容哈希、重复文件复用、本地文本缓存 | 当前Codex从原资料整理有来源的事实 |
| 理需求 | 事实表、缺项表、任务包；新资料触发核对 | 不能把AI建议直接当客户已确认事实 |
| 找模板 | 复用已有本地命名检索；本单可直接使用客户模板 | 无模板时需要查看少量候选预览 |
| 制作 | 导入PPTX并精确替换现有文本；保留页面结构和页数 | 新布局、图表、图片处理由当前Codex按对应技能制作后接回 |
| 修改 | 锁定版本和事实版本、记录修改类型、输出新版本 | 根据原话判断哪些页应改，不默认重做全稿 |
| 检查 | 结构/字体校验、最终文字核对、每页导出预览 | 当前Codex看图，本人确认业务内容与交付效果 |
| 交付 | 样稿/终稿区分，本地PPTX和ZIP包，审核绑定文件指纹 | 实际发送、客户验收单独登记 |
| 收款与经验 | 总价、到账、待收分开；人工分钟/费用记录；候选经验 | 历史未知成本保留未知，跨单验证后再推广 |

未接入闲鱼消息监听、自动报价发送、投流、无人值守制作或独立模型API。首版不需新增API密钥；当前Codex对话仍使用账号额度。本地解析、修改和打包本身不调用额外模型。

## 给执行者的命令顺序

在本工作区终端中使用。所有命令均可由当前Codex代运行。

```powershell
.\工作流.ps1 new XY-PPT-新编号 --brief examples/新订单需求.json
.\工作流.ps1 source XY-PPT-新编号 'E:\客户资料\模板.pptx' --role template
.\工作流.ps1 source XY-PPT-新编号 'E:\客户资料\需求.md' --role content
.\工作流.ps1 reconcile XY-PPT-新编号 订单资料核对.json
.\工作流.ps1 packet XY-PPT-新编号
.\工作流.ps1 inspect XY-PPT-新编号 资料编号
.\工作流.ps1 build XY-PPT-新编号 本轮制作计划.json
.\工作流.ps1 review XY-PPT-新编号 版本编号 实际检查记录.json
.\工作流.ps1 package XY-PPT-新编号 版本编号 --draft
.\工作流.ps1 dashboard
```

示例中的文件路径、资料编号、版本编号要取实际值，不能直接复制占位符。无缺项且全稿检查通过才移除 `--draft` 生成终稿包。

编辑计划的实际例子见演示订单plans/v1.json和v2.json。必须有base_ref、base_sha256、fact_revision、purpose、changes；每个change使用inspect实际返回的anchor_id及old_text/new_text。新布局或页数变化不由这个文本适配器强行实现。

复杂制作可在订单build目录按Presentations技能完成，然后：

```powershell
.\工作流.ps1 register XY-PPT-新编号 'E:\制作输出\成稿.pptx' --note '本轮制作说明' --base-ref 原版本编号
```

登记后同样需要inspect/实际检查/review/package。不要把“文件可读取”当“全稿已审核”。

记录账款和经验使用record：
- finance：agreed_total、evidence。
- payment/cost：唯一id、amount、evidence；time：唯一id、minutes、evidence，估计用时加estimated=true。
- sent/accepted：delivery_id、evidence。仅记录真实已发生动作，不代替发送。
- learning：observation、action、result、next_validation，可加source。

## 节省上下文的约定

本地提取与缓存不消耗同等体量的模型Token；只把相关事实、缺项和少量候选交当前任务。任务包JSON控制在12000字符以内（不是Token数），超出会明示省略项及完整记录路径，执行者必须按需要补读。不把整个历史聊天、素材库、原始解析日志塞进每次制作。

客户指定模板时跳过图库检索。本轮任务包实测约4520字符，包含订单、少量事实、3份来源路径、2个版本及7条简短规则；不含客户沟通全文。

## 失败与恢复

- 文件指纹变化：将新文件作为新资料或新版本登记，不复用旧审核。
- 新资料未核对/事实过期：先reconcile，再确定继续哪版；不要直接放行交付。
- 结构、字体或文字检查失败：查看对应build/运行编号/adapter.log。失败文件不会作为有效版本登记；修复后重跑会另建运行目录。
- 不确定哪个版本已发给客户：向本人核定；不能选名字看起来最新的文件。
- 运行时升级导致路径失效：调用load_workspace_dependencies，更新config/runtime.json；不改模型或密钥配置。
- 锁文件存在：先检查是否有运行中进程；仅确认上次已退出后清理该订单锁。不要删除运行中的锁。
- 工作台为快照，双击入口或dashboard刷新。
