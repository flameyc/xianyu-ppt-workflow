# 首单制作复盘与执行标准

更新：2026-09-13。依据：用户指定的首单任务本地记录、已有指定客户微信FTS导出、原18页成稿总览、本轮用户补充。原聊天和原图留本机。以下因果解释是候选经验，不能用一个案例证明利润或转介绍率改善。

## 判断

用户报告首单获得好评并带来推荐客户；私聊可见同意留评及推荐朋友的消息，未另查平台评价。原制作具备统一学生/AI角色、纸张拼贴、情境叙事、视觉比喻、互动任务和有变化的版式。客户要求“生动有趣”，先认可首页再继续整套。这些是应延续的成功做法。

此前系统的两份内部重制重视原生文字与结构检查，但没有充分延续已经认可的视觉语言。简洁文字版不能仅因测试通过就称为效果更好。用户现在要求简单单也适度超预期：价格决定追加投入与范围，不能自动把风格简化成纯文字。

## 还原流程与可复用做法

| 原流程 | 有效之处或问题 | 新流程落点 |
|---|---|---|
| 先读文案，做文字制作方案 | 可以先理内容，但后拿到原教案导致标题和环节返工 | 开始核定最高优先级内容来源；改写建议与客户指定文案分开 |
| 分析参考图，再做首页样图 | 把“生动有趣”变为人物行动、纸张风格、视觉隐喻 | 保存参考特点；先封面＋代表内容页验证，不只看漂亮封面 |
| 首页认可后批量扩展 | 统一角色和视觉语言，降低全套方向错误 | 锁定样稿版本与确认来源；按情境/方法/互动等页型复用 |
| 后续按教案改标题、环节与活动细节 | 内容匹配比AI自创教学方案更重要 | 逐页内容来源表；检查活动指令、练习步骤和承上启下 |
| 图片后转可编辑稿 | 能保留插画，但后补文字层增加成本 | 从样稿开始分离无字背景/插画与原生文字、卡片、编号 |
| 导读与正式课拆分出现漏页、页码歧义 | 任务说完成不等于实际发送版本完整 | 稳定页ID（如INTRO-01/LESSON-03）＋成稿页码映射＋实际交付文件哈希 |
| 客户局部调整，原画面尽量保留 | 局部改文案能避免风格漂移 | 先判断改文字、简单结构还是插画；无需重生成时直接改原生层 |
| 获得正向反馈与转介绍 | 满足用途、样稿确认和及时修改可能共同起作用 | 分开记录满意度、推荐线索与实际成交，不把推荐自动记新订单收入 |

原任务中有“23页已全部补齐”的助手报告，客户后续仍针对18页版本反映缺导读。因此不能只抄历史助手结论；以实际文件、发送版本与客户反馈核实。原稿总览只足以复盘视觉方向，不代表本轮逐页重新验收。

## 每单执行清单

1. **接资料**：读本单消息，取明确附件，保留来源/时间/版本；提取受众、用途、交期、计费范围、输出格式、编辑边界、参考风格和客户原话。
2. **核对**：明确文案是否可改、标题是否原样、导读是否计入页数；列来源冲突。缺资料可做明确标记的样稿，不能假装完整终稿。
3. **做样稿**：两路线都可网页协作；通常做封面和代表内容页，密集/互动需求增加对应样页。网页合同见项目skill。样页优先表达客户内容，不只装饰。
4. **锁风格**：保存认可样页与证据，确定角色、字体、配色、视觉元素、页型、文字层边界。已有认可方向直接复用。
5. **扩整套**：用统一内容表＋素材复用；普通文字与图形原生可编辑，复杂插画图片化。审美亮点优先封面、关键页和恰当情境图，不默认每页另生一张图。
6. **核验**：检查章节齐全、文案与活动步骤、总页数和页码映射；看最终PPT渲染的全页；核对风格与样稿一致；确认客户软件与真实可编辑边界。
7. **改稿**：反馈绑定版本和页ID；区分制作错误、范围内调整、新增需求与新事实。优先保留客户满意部分；重大风格改变重新取样稿确认。
8. **交付复盘**：本地打包后由本人发送，实际验收与收款另记。提炼“观察→动作→结果→下次验证”，保留未知工时和成本。

## 简单单怎样超预期

优先做边际投入低的改进：封面更有设计感、统一图标配色、复用合适人物素材、把重点文字改成图解、改善留白与层级。不要为压低路线成本舍弃客户已确认的插画方向。价格低也不代表只能套纯文字模板。

新增大量原创插画、持续探索不同方向、增加页面或承诺动画会扩大投入，需要结合本单范围判断。超预期不自动修改报价，也不默认新增售后次数。Token可能相近，但图像生成、人工时间和返工成本仍需分别记录。

## 做单时怎样成长

每单结束只补六项：客户最在意什么；哪张样页被选中；实际改了哪些页/原因；复用了什么；人工分钟与可得用量；客户结果。由Codex从记录预填，本人只补未知和最终评价。

经验先作为候选，下一单记录触发条件、是否采用和结果；多单有效再写通用规则。审美偏好按客户/行业/用途保存，不能把一个教学客户喜欢的手账风强加给商务客户。保留失败案例，例如“结构通过但参考风格不符”，用于下单前检查。
