# 在不同会话继续任务

仓库：`flameyc/xianyu-ppt-workflow`，设为私有。只有具有访问权限并实际读取仓库的会话才能取得这些记录，单纯贴链接不保证任意产品有仓库访问权限。

## 给新会话的一句话

> 继续建设这个仓库的闲鱼PPT自动化系统。先读AGENTS.md、CURRENT_STATE.md和执行计划书.md第2节，说明目前最值得推进的一步并直接执行。复用已有成果，先制作后获客，不重扫模板库，不把内部回放当真实客户验收。结束时更新进度和变更记录；需要同步到GitHub时核对暂存文件再提交推送。

同一台机器优先直接打开原工作区 `E:\技术\闲鱼PPT自动化系统`，这样本地客户订单仍在。另一台机器克隆后可继续工程开发，但需另行提供所需客户文件，不能假设原盘符可访问。

## 新机器开始

```bash
git clone https://github.com/flameyc/xianyu-ppt-workflow.git
cd xianyu-ppt-workflow
python -m unittest discover -s tests -v
python workflow.py dashboard
```

订单与路由测试只需要Python 3.11或更新版本的标准库。PPT制作还需要本机可用的Node、`@oai/artifact-tool`和Presentations技能；这些是当前Codex工作环境提供的依赖，本仓库不携带其私有安装包或许可。先由当前会话调用工作区依赖加载工具，再用下面的脚本写本机配置：

```bash
python tools/configure_runtime.py --python /绝对路径/python --node /绝对路径/node --node-modules /绝对路径/node_modules --skill-dir /绝对路径/presentations
```

参数使用真实绝对路径。原机已存在 `config/runtime.json`，无需覆盖。脚本默认拒绝覆盖，确实重新配置时加 `--overwrite`。

微信读取器仍依赖原机指定目录下的外部读取模块、现成Crypto依赖、有效的本机密钥和账号匹配。尚未做成跨机器即装即用的连接器；没有这些材料时跳过微信读取，使用本人提供的资料。不要索要密钥贴到聊天或GitHub。

## 哪些文件不在GitHub

`.private/`、`orders/`、`cache/`、`learning/`、`reports/`、运行时配置、媒体附件与一次性客户重制脚本均被忽略。原机原有文件照常存在，不移动或删除。技术文档中的本地报告、旧订单和知识库链接只在原机有效；云端概况看 `CURRENT_STATE.md` 和 `docs/验证与案例摘要.md`。

## 每次接力的收尾

1. 核对 `git status --short`，不覆盖其他会话未提交改动。切换机器前先提交并推送，接手时在干净工作区拉取。
2. 更新 `CURRENT_STATE.md`（当前状态）、`执行计划书.md`（唯一建设清单）和 `CHANGELOG.md`（本次变化）。不另开相互矛盾的TODO清单。
3. 暂存明确的源码与文档，运行 `python tools/check_repo_boundary.py` 检查Git暂存内容；检查失败先修正。
4. 运行相应测试，提交后再push。不使用强制推送、reset --hard或清理未跟踪客户文件的命令。

首次入库保留29项已有工作流测试，并增加3项仓库边界检查测试，32项均通过；34个暂存文件检查未发现禁止路径或常见密钥模式。检查是有限的文件与常见敏感模式检查，不是对所有潜在秘密的绝对保证。
